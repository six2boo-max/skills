# Report Branching — 보고서에서 뻗어나가기

목표: 사용자의 보고서를 출발점으로, **보고서를 더 좋게 만들 다음 주제**를 찾아 근거와 함께 돌려주는 것.
일반 조사와 달리 질문은 보고서 안에서 나온다. 보고서와 상관없는 흥미로운 이야기는 가지로 고르지 않는다.

## 1. 보고서 받기

- 받는 방식: 대화에 붙여넣기, 저장소 안 파일 경로, 업로드한 PDF·Word 파일, 링크.
  - PDF·Word는 `pdf`·`docx` 스킬로 텍스트만 뽑아 읽는다.
  - 링크는 `WebFetch`로 본문만 뽑는다. claude.ai 문서·아티팩트 링크는 해당 도구로 읽는다.
- 보고서가 없으면 그것만 묻고 멈춘다.
- 사용자가 집중할 방향(예: "반론 위주", "국내 사례")을 말하면 그 방향을 우선한다.

## 2. 보고서 분석 (검색 전, 머릿속에서만)

아래를 뽑는다. 사용자에게 길게 설명하지 않는다.
- 핵심 주장 3~5개, 각 주장의 근거와 그 근거의 날짜
- 빈틈: 근거가 없는 주장, 1년 넘은 수치, 빠진 이해관계자·지역·기간, 다루지 않은 반론
- 보고서가 끝에서 열어둔 질문이나 "향후 과제"

## 3. 가지 후보 만들기와 고르기

후보를 6~10개 만든다. 유형은 다음 여섯 가지다.

| 유형 | 뜻 |
|---|---|
| 심화 | 핵심 주장 하나를 한 단계 더 깊게 (원인, 메커니즘, 세부 데이터) |
| 최신화 | 보고서의 수치·사건 이후 새로 나온 자료 |
| 반론·리스크 | 주장을 반박하거나 약하게 만드는 근거, 실패 사례 |
| 사례 | 다른 기업·나라·분야에서 같은 현상이 나타난 실제 사례 |
| 인접 분야 | 보고서 주제가 영향을 주거나 받는 옆 분야 |
| 다음 질문 | 보고서 결론을 받아들이면 자연스럽게 생기는 후속 질문 |

각 후보를 **보고서와의 연결성**과 **결론을 바꿀 가능성**으로 매겨 상위 몇 개를 고른다. 한 유형만 고르지 말고 섞는다.
고른 가지 수는 아래 예산을 따른다. 고르지 않은 후보는 버리지 말고 보고서 끝 "다음에 파볼 가지"에 남긴다.

## 4. 예산

사용자가 단계를 말하지 않으면 standard로 한다.

| 단계 | 조사할 가지 | 검색 합계 | 페이지 열기 합계 |
|---|---|---|---|
| quick | 2개 | 최대 5회 | 최대 1개 |
| standard | 3개 | 최대 10회 | 최대 3개 |
| deep | 5개 | 최대 20회 | 최대 6개 |

예산을 넘기려면 먼저 사용자에게 묻는다.

## 5. 조사 규칙 (토큰 절약)

- **가지별 첫 검색은 한 턴에 모두 병렬로** 보낸다. 두 번째 검색은 결과가 부족한 가지에만 보낸다.
- 검색은 `standard` 모드가 기본이다. 결과가 빈약하거나 오래됐을 때, 또는 최신화 가지일 때만 `extended`를 쓴다.
- 검색 결과 요약으로 답이 되면 페이지를 열지 않는다. 페이지를 열면 원문이 통째로 들어와 토큰이 많이 든다. 수치·표처럼 요약에 없는 것이 꼭 필요할 때만 연다.
- 공식 통계, 논문, 기관 보고서, 신뢰도 높은 언론을 우선한다.
- 서브에이전트(Agent 도구)나 `deep-research` 스킬을 부르지 않는다.
- 보고서에 이미 있는 내용은 다시 찾지 않는다.
- 가지마다 서로 다른 출처 2개가 일치하거나 1차 자료 1개를 찾으면 그 가지는 끝낸다.

## 6. 결과 형식

사용자가 쓴 언어로 쓴다. 기본은 채팅 답변이고, 사용자가 요청할 때만 문서나 파일로 만든다.

```
## 보고서 핵심
(보고서가 말하는 바를 2~3줄로. 내가 제대로 읽었는지 사용자가 확인할 수 있게)

## 확장 가지 지도
| # | 가지 | 유형 | 왜 중요한가 (보고서의 어느 부분과 연결되는지) |
|---|---|---|---|

## 가지별 조사 결과
### 1. <가지 이름> (유형)
- 찾은 내용 [1]
- 찾은 내용 [2]
- **보고서에 넣는다면:** <어느 섹션 뒤에, 어떤 문장·표·그래프로>
- **더 파볼 질문:** <한 줄>

### 2. ...

## 보고서에서 고칠 점
(조사 중 보고서의 수치가 오래됐거나 주장이 반박된 것을 발견했을 때만. 없으면 이 섹션을 뺀다)

## 다음에 파볼 가지
- <고르지 않은 후보> — 한 줄 이유

## 출처
[1] 제목 — URL (날짜)
```

- 수치·날짜·가격에는 반드시 출처 번호를 단다.
- 확인하지 못한 것은 추측으로 채우지 말고 "확인 못 함"이라고 적는다.
- 마지막 줄에 사용량을 적는다. 예: `가지 3개 · 검색 8회 · 페이지 2개 (standard)`
- 끝에 한 줄로 다음 행동을 제안한다. 예: "2번 가지를 deep으로 더 파볼까요?"
